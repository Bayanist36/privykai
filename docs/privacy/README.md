**Текущее решение (23.10.2026; редакция 1.1 — 03.11.2026):** оператор — Суханов Владимир Владимирович; контакт — `vladimir__suhanov@mail.ru`; хостинг — GitHub Pages; системное резервное копирование оставляем. `docs/privacy/index.html` уже собран с этими данными и проверен — владельцу осталось выполнить раздел 5 и получить URL. Для действующего репозитория `Bayanist36/privykai-privacy` подготовлена идентичная копия `docs/privacy/privykai-privacy.html`.

## 1. Собрать страницу

Нужен PowerShell 7 (в проекте уже используется для сборки APK). Из корня проекта:

```powershell
pwsh -NoProfile -File scripts/build_privacy_page.ps1 `
  -OperatorName "ИП Иванов Иван Иванович" `
  -ContactEmail "privacy@example.ru"
```

Скрипт:

- подставляет имя оператора и e-mail;
- ставит дату редакции (текущую, можно передать `-EffectiveDate "23 октября 2026"`);
- удаляет баннер «Черновик»;
- проверяет, что не осталось `{{...}}`, есть все обязательные разделы, русский язык, UTF-8, нет внешних скриптов, стилей, картинок и ссылок;
- пишет `docs/privacy/index.html` в UTF-8 без BOM и печатает SHA-256.

Проверить уже собранную страницу без пересборки:

```powershell
pwsh -NoProfile -File scripts/build_privacy_page.ps1 -CheckOnly
```

Если в шаблоне остались `{{...}}` или баннер «Черновик», проверка завершится ошибкой. Это защита от публикации незаполненной страницы.

Локальный просмотр: откройте `docs/privacy/index.html` в браузере. Внешние ресурсы не нужны, страница работает из файла.

## 2. Что должен заполнить владелец

Имя оператора и e-mail нельзя придумать за владельца: они попадут в публичный документ и в карточку RuStore.

| Поле | Как определить | Пример |
|---|---|---|
| `OperatorName` | Юридическое имя владельца аккаунта RuStore: ФИО для физлица, «ИП …» для ИП, полное название для ООО | `ИП Иванов Иван Иванович` |
| `ContactEmail` | Рабочий ящик, который реально читают. Он публикуется в политике и в карточке | `privacy@example.ru` |
| `EffectiveDate` | Необязательно. По умолчанию — дата сборки | `23 октября 2026` |

Если владелец ещё не решил, физлицо он или ИП/юрлицо, сначала нужно решение по аккаунту: от него зависит формулировка оператора. Это же решение указано в чек-листе SUK-12.

## 3. Требования RuStore к политике (проверено)

Официальные правила RuStore, раздел 5.1 «Политика конфиденциальности» (снимок страницы от 23.10.2026):

> Приложения, осуществляющие сбор или обработку персональных данных пользователей, должны содержать политику конфиденциальности. Политика конфиденциальности должна:
> - быть доступна по ссылке в карточке приложения и внутри приложения;
> - быть размещена на русском языке;
> - содержать сведения о категориях собираемых персональных данных, целях их обработки, сроках хранения, порядке удаления, а также контактные данные лица, ответственного за обработку персональных данных.
>
> Основание: ФЗ-152 «О персональных данных».

Источник: `https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps` (раздел 5.1; прямой доступ из рабочего окружения блокируется, страница сверена по архивному снимку официального домена).

Что это значит практически:

1. **Ссылка в карточке.** Публичный URL обязателен. Поле в Консоли принимает ссылку; точный формат валидации публично не описан — проверяется при заполнении.
2. **Ссылка внутри приложения.** RuStore формально требует ссылку и внутри приложения. В SUK-28 экран политики переписан под редакцию 1.1 и показывает публичный URL (`AppInfo.privacyPolicyUrl`) выделяемым текстом: приложение не открывает сеть и не запрашивает `INTERNET`, адрес можно скопировать и открыть в браузере. Локальный текст остаётся: он работает офлайн.
3. **Русский язык.** Страница полностью на русском.
4. **Состав.** В тексте есть категории данных, цели, сроки хранения, порядок удаления и контакт ответственного лица.
5. **Доступность.** Ссылка должна открываться без авторизации, без VPN и без приложения RuStore. HTTPS обязателен де-факто: без него браузеры и модерация получают небезопасный ресурс. Проверяйте с российского мобильного интернета, а не только с рабочего Wi-Fi.

Приложение не собирает данные, но политика всё равно нужна: RuStore проверяет её наличие у приложений, работающих с данными пользователя, и требует ссылку в карточке. Пустое поле — риск отказа.

## 4. Бесплатный хостинг: три варианта

| Критерий | GitHub Pages (рекомендую) | Cloudflare Pages | Netlify Drop |
|---|---|---|---|
| Цена | 0 ₽ | 0 ₽ | 0 ₽ |
| Аккаунт | GitHub; для бесплатного тарифа репозиторий должен быть публичным | Cloudflare | Netlify (для сохранения и обновления сайта) |
| HTTPS | Да, автоматически | Да, автоматически | Да, автоматически |
| Свой домен | Можно позже | Можно позже | Можно позже |
| Обновление | Заменить `index.html` в репозитории | Новый деплой | Перетащить папку заново |
| Плюсы | Прозрачно, версионируется, бесплатно, знакомо модерации | Быстрый CDN, не нужен Git | Самый быстрый старт без Git |
| Риски | Публичный репозиторий; доступность из РФ нужно проверить | Нужен аккаунт Cloudflare; проверьте доступность из РФ | Случайный адрес; без аккаунта сайт легко потерять |

**Рекомендация:** GitHub Pages. Он бесплатный, отдаёт HTTPS и позволяет хранить историю изменений политики. Если из вашей сети GitHub открывается нестабильно, берите Cloudflare Pages: тот же статический файл, другой CDN.

### 4.1. GitHub Pages — пошагово (без Git)

1. Войдите в GitHub или создайте аккаунт.
2. **New repository** → имя, например `privykai-privacy` → видимость **Public** (на бесплатном тарифе Pages работает только в публичном репозитории) → **Create repository**.
3. В репозитории: **Add file → Upload files**. Перетащите `docs/privacy/index.html`. Важно: файл должен называться `index.html` и лежать в корне репозитория.
4. **Commit changes**.
5. **Settings → Pages**.
6. **Build and deployment → Source: Deploy from a branch**. **Branch: `main`**, папка **`/ (root)`**. **Save**.
7. Подождите 1–10 минут. На странице Pages появится адрес вида `https://<username>.github.io/privykai-privacy/`.
8. Откройте адрес в режиме инкогнито, без входа в GitHub. Проверьте с телефона на мобильном интернете.
9. Скопируйте URL: он нужен в карточке RuStore и в приложении.

Обновление: загрузите новый `index.html` поверх старого и сделайте commit. Адрес не меняется. Не удаляйте репозиторий и не переключайте Pages на private: сайт станет недоступен.

### 4.2. Cloudflare Pages — пошагово

1. Войдите в Cloudflare Dashboard → **Workers & Pages → Create → Pages → Upload assets**.
2. Название проекта, например `privykai-privacy`.
3. Перетащите папку `docs/privacy` целиком (внутри должен быть `index.html`) → **Deploy**.
4. Получите адрес `https://privykai-privacy.pages.dev` (или похожий). Проверьте HTTPS и доступ без входа.
5. Для обновления: **Create new deployment** и загрузите папку заново.

### 4.3. Netlify Drop — пошагово

1. Откройте `https://app.netlify.com/drop`.
2. Перетащите папку `docs/privacy` с `index.html`.
3. Дождитесь адреса вида `https://<random>.netlify.app`.
4. Войдите в Netlify и **claim** сайт, иначе его сложно обновлять и можно потерять. Переименуйте сайт в понятный (`privykai-privacy`).
5. Проверьте HTTPS и доступ без входа.
6. Для обновления: **Deploys → Drag and drop** новой папки.

## 5. Чек-лист владельца аккаунта

Порядок действий, после которого URL заработает:

- [ ] Решить тип аккаунта RuStore: физлицо, ИП или юрлицо.
- [ ] Записать точное юридическое имя оператора и рабочий e-mail, который будет публично указан.
- [ ] Собрать страницу командой из раздела 1 с этими значениями. Убедиться, что проверка прошла и в `index.html` нет `{{...}}`.
- [ ] Выбрать хостинг (по умолчанию GitHub Pages) и создать аккаунт.
- [ ] Загрузить `index.html` и включить HTTPS.
- [ ] Открыть публичный URL в инкогнито, на телефоне и с российского мобильного интернета. Убедиться, что нет логина, ошибок и предупреждений сертификата.
- [ ] Проверить, что на странице видны: оператор, e-mail, категории данных, цели, сроки хранения, удаление, контакт.
- [ ] Вставить URL в карточку RuStore (поле политики конфиденциальности).
- [ ] Передать URL разработчику, чтобы на экране «Политика конфиденциальности» появилась кнопка открытия публичной страницы в браузере (SUK-13).
- [ ] Сохранить URL в документах проекта и в менеджере паролей/базе знаний. Не терять доступ к хостингу.
- [ ] После публикации приложения проверить ссылку ещё раз с телефона.

Ориентир по времени: 20–40 минут, если аккаунт GitHub уже есть. Если аккаунта нет — плюс 10 минут на регистрацию и подтверждение e-mail.

## 6. Что проверить перед публикацией

- [ ] В `index.html` нет `{{OPERATOR_NAME}}`, `{{CONTACT_EMAIL}}`, `{{EFFECTIVE_DATE}}`.
- [ ] Нет баннера «Черновик».
- [ ] Дата редакции соответствует дате публикации.
- [ ] Указан реальный e-mail, а не `example.com`.
- [ ] На странице нет внешних шрифтов, скриптов, картинок и счётчиков.
- [ ] HTTPS-замок в браузере, нет предупреждения сертификата.
- [ ] Страница открывается без авторизации и без VPN.
- [ ] Ссылка не ведёт на PDF, Google Docs, Яндекс.Диск или файл, который может стать приватным. Нужна обычная HTML-страница.
- [ ] URL не содержит параметров сессии, `?usp=sharing` и подобных.
- [ ] После смены оператора или e-mail страница обновлена, дата редакции изменена.

## 7. Ограничения и честные оговорки

- Скрипт собирает и проверяет страницу, но **не публикует** её: для этого нужен аккаунт владельца.
- Юридическую формулировку оператора (ФИО/ИП/ООО) владелец подтверждает сам; маркетолог не заменяет юриста.
- GitHub Pages записывает IP-адреса посетителей в журналы безопасности. Это указано в подвале страницы; сама страница не использует cookie и аналитику.
- Если в приложении появится аналитика, реклама, аккаунты или сеть, политику нужно переписать до релиза. Текущий текст описывает версию 1.1.0, включая экспорт/импорт JSON и виджет главного экрана.
- Встроенный экран политики в приложении (`lib/features/settings/presentation/screens/privacy_policy_screen.dart`) синхронизирован с редакцией 1.1 в SUK-28: краткий офлайн-пересказ, оговорки про файл экспорта и системный backup, URL полной редакции из `AppInfo.privacyPolicyUrl`. Тест `test/features/settings/presentation/screens/privacy_policy_screen_test.dart` следит за отсутствием абсолютной формулировки.

## 8. Редакция 1.1: что изменилось и что публиковать

Редакция 1.1 от 03.11.2026 дополнена сведениями о версии 1.1.0:

- экспорт и импорт JSON-резервной копии: файл создаётся по команде пользователя, место сохранения или передачи выбирает пользователь, приложение само файл никуда не отправляет;
- импорт читает только выбранный пользователем файл, проверяет формат `pryvykai-backup` и версию схемы 1, заменяет данные только после подтверждения;
- виджет главного экрана показывает прогресс, серию и названия привычек (до трёх в широком варианте, одну в компактном состоянии серии); содержимое видно тому, у кого есть доступ к разблокированному телефону;
- названия привычек видны в уведомлениях; добавлена подсказка, как скрыть содержимое на экране блокировки средствами Android;
- системное резервное копирование Android может копировать данные в аккаунт Google; это делает ОС, а не приложение;
- удаление приложения не удаляет экспортированный файл и системную копию;
- приложение по-прежнему не содержит рекламы, аналитики и сторонних SDK, собирающих данные, и не запрашивает `INTERNET`.

Файлы для публикации:

| Файл | Куда | Примечание |
|---|---|---|
| `docs/privacy/index.html` | Новый репозиторий или папка сайта | Имя для GitHub Pages по умолчанию; открывается по адресу каталога. |
| `docs/privacy/privykai-privacy.html` | Репозиторий `Bayanist36/privykai-privacy`, корень | Идентичная копия под текущий URL `.../privykai-privacy/privykai-privacy.html`. |

Оба файла побайтно одинаковы (SHA-256 `A92CE5A6D1FB02AEE5178BF9631CE8553338AA2EA34226C79333E3A6A91E77C7`). Для обновления действующей страницы достаточно заменить `privykai-privacy.html` в корне репозитория и сделать commit. После публикации проверьте URL в инкогнито и с телефона.
- Системное резервное копирование Android может копировать данные приложения в аккаунт Google, если пользователь его включил. Это отражено в политике. Если владелец хочет убрать оговорку, разработчик может отключить `android:allowBackup`, но тогда пользователь потеряет резервную копию привычек.
