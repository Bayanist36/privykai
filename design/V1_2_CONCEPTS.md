## 1. Статистика v1.2

### Что меняется

- Переключатель **«7 дней / 30 дней»** вместо жёстких 7 дней. Период влияет на
  сводку и тренд; хитмап всегда показывает 12 недель — это исторический контекст,
  а не выбранный период.
- **Тренд** — 7 столбцов по дням (процент закрытых запланированных слотов).
  Значение подписано над столбцом; цвет не единственный носитель.
- **Хитмап** — 12 недель × 7 дней. Уровни: 0 — нет запланированных привычек,
  1 — <34 %, 2 — 34–66 %, 3 — 67–99 %, 4 — 100 %. Сегодня обведён `ink900`.
  Легенда «меньше / больше» и месяцы.
- **Цели недели** — карточка привычки с недельной целью: «2 из 3 · осталось 1 раз»,
  три сегмента, недельная серия.
- Список «По привычкам» остаётся; у цели вместо «Серия X · лучшая Y» —
  «Цель 3 раза в неделю · 2 из 3».

### Данные

| Показатель | Формула |
|---|---|
| День, % | `completedScheduled / scheduledSlots` за календарный день |
| Тренд, % | то же за каждый из 7 дней, включая сегодня |
| Сводка | как в v1.1, но за выбранный период (7/30) |
| Хитмап | те же дневные проценты за 12 недель; незапланированные дни — нейтральные |
| Недельная цель | `completedThisWeek / weeklyGoal`, максимум 1,0 |

### Состояния

- Нет привычек — пустое состояние + CTA (как сейчас), без пустых графиков.
- Нет отметок — сводка 0 %, тренд по нулям, хитмап пустой; подпись «Отметьте
  первую привычку — здесь появится прогресс».
- Загрузка — skeleton сводки, тренда и трёх карточек.
- Ошибка — полноэкранно + «Повторить»; не показывать пустое состояние (см. ST-01).

### Доступность

- Столбцы тренда — `Semantics` с меткой «Вторник, 4 из 5, 80 %»; хитмап — сводка
  «12 недель, 78 %, пропущено 4 запланированных дня».
- Уровни хитмапа различимы не только цветом: подпись и легенда.
- Переключатель периода — `SegmentedButton` с `selected` и «7 дней / 30 дней».

### Рамки

- Никаких фильтров по привычкам, экспорта графика и сравнения периодов — это
  следующий шаг, не 1.2.
- Графики только для просмотра, без тапа/тултипов: меньше кода и не нужен
  отдельный жест.

## 2. Цели «3 раза в неделю»

### Продуктовое решение (требует подтверждения)

Сейчас расписание — «каждый день» или выбранные дни. Цель «3 раза в неделю» —
это **третий режим повторения**, а не добавка к дням недели:

| Режим | Поле | Поведение |
|---|---|---|
| Каждый день | `weekdaysMask = 127` | как сейчас |
| Дни недели | `weekdaysMask != 127` | как сейчас |
| **N раз в неделю** | `weeklyGoal = 1…7`, `weekdaysMask` не используется | привычка доступна каждый день, цель — N отметок за неделю |

Нельзя одновременно «Пн/Ср/Пт» и «3 раза в неделю»: это два разных обещания.
При выборе цели дни скрываются; при возврате к дням цель сбрасывается.
**Это решение по модели данных нужно согласовать с DeepSeek Agent и
разработчиком до реализации.**

### Поведение

- В «Сегодня» цели живут отдельным блоком **«Цели недели»** под обычным списком.
  Карточка: эмодзи, название, «2 из 3 на этой неделе», три сегмента,
  «Осталось 1 раз».
- Дневной прогресс «Выполнено сегодня X из Y» **не включает** цели недели:
  иначе 2 из 3 выглядит как 2 из 3 сегодня. Это осознанное разделение.
- После закрытия цели карточка остаётся, но получает состояние «Цель недели
  выполнена»; дополнительные отметки разрешены, но не увеличивают прогресс выше 3/3.
- Новая неделя начинается в понедельник 00:00 локального времени. В понедельник
  прогресс 0/3, серия пересчитывается.
- Серия — **недельная**: «2 недели подряд». Лучшая — по неделям. Дневная серия
  для такого режима не показывается.
- Напоминание: одно в день в выбранное время; после закрытия цели на неделе
  оставшиеся уведомления отменяются, при снятии отметки — возвращаются.
- Вечернее напоминание не зависит от целей; тихие часы применяются как обычно.

### Модель данных (предложение)

```dart
enum HabitRepetition { daily, weekdays, weeklyGoal }

class Habit {
  // было: weekdaysMask
  HabitRepetition repetition; // default weekdays для старых записей
  int weekdaysMask;           // используется при weekdays
  int? weeklyGoal;            // 1..7, только weeklyGoal
}
```

Миграция: старые привычки `mask == 127` → `daily`, иначе `weekdays`; `weeklyGoal = null`.
Никаких изменений в отметках: `completedDates` остаются календарными.

### Крайние случаи

- Цель 7 — фактически «каждый день», но серия недельная; подсказать в форме
  «Проще выбрать „Каждый день“?».
- Цель 1 и 7 дней подряд — прогресс не больше 1/1; дополнительные отметки видны
  в истории, но не в цели.
- Смена цели в середине недели: прогресс текущей недели сохраняется, цель
  пересчитывается; если новая цель ниже уже сделанного — сразу «выполнено».
- Удаление привычки удаляет и недельную историю; восстановления нет.
- Часовой пояс/переход через полночь: неделя по локальной дате; при смене
  часового пояса пересчитать границы.

### Что не входит

- Гибкие цели «2 раза в месяц», «каждые 3 дня».
- Несколько целей на одну привычку.
- Автоматическое распределение по дням («предложить дни под цель»).

## 3. Тихие часы

### Зачем

В 1.1 появились интервальные напоминания: «каждые 2 часа с 08:00 до 22:00».
Если окно заканчивается позже 22:00 или начинается раньше 08:00, приложение
будит ночью. Тихие часы — глобальный фильтр, а не переделка интервального блока.

### Как встроено в v1.1

- **Не меняем** карточку напоминания в форме: старт, конец, интервал остаются
  как сделал разработчик (`habit_form_screen.dart:891-963`).
- В форме под интервалом — одна информационная строка: «Напоминание в 08:00.
  Ночью не беспокоим: тихие часы 22:00–08:00». Без второго переключателя.
- В «Настройках» в группе «Напоминания» появляется строка **«Тихие часы»** со
  значением «22:00–08:00»; тап открывает отдельный экран.
- Тихие часы **глобальные**, не на привычку: меньше настроек и понятнее
  ожидание «ночью не будит всё приложение».

### Экран

| Блок | Содержание |
|---|---|
| Интро | Луна в зелёной плашке, «Не беспокоим ночью», объяснение в 2 строки |
| Переключатель | «Тихие часы · Для всех напоминаний», по умолчанию включён |
| Время | Две крупные кнопки «Начало 22:00» / «Конец 08:00»; конец может быть на следующий день |
| Шкала | 24 часа: заштрихованная тишина 22:00–08:00, зелёное разрешённое окно, точки напоминаний; 23:00 приглушена |
| Пояснение | «Первое напоминание после тишины — в 08:00. Пропущенные ночные повторы не сдвигаются и не копятся» |
| Что учитывается | Интервальные, обычные и вечернее напоминание |
| Предупреждение | Если всё окно привычки попадает в тишину — напоминаний не будет; привычку можно отметить вручную |
| Футер | «Применяется сразу · можно изменить в любой момент» |

### Правила

`quietStart = 22:00`, `quietEnd = 08:00` (минуты от полуночи, 1320 и 480).
Окно может пересекать полночь.

```
isQuiet(m):
  if !enabled: return false
  if start < end: return start <= m < end
  return m >= start || m < end

nextAllowed(times):
  return times.where((m) => !isQuiet(m))
```

- Пропущенные слоты **не сдвигаются** на конец тишины: в 08:00 придёт только
  тот слот, который по расписанию совпадает с 08:00. Иначе пользователь получит
  пачку уведомлений утром.
- Если после фильтра слотов не осталось — уведомлений нет; привычка и серия
  работают, отметка вручную доступна.
- Вечернее напоминание тоже фильтруется. При дефолтных 20:00 и 22:00–08:00 оно
  не затронуто.
- Границы: 08:00 — уже можно (`m >= end`), 22:00 — уже тишина (`m >= start`).
- Начало = конец — невалидное окно; inline-ошибка «Начало и конец не могут
  совпадать», настройка не сохраняется.
- Смена часового пояса: пересобрать расписание; тихие часы остаются локальными.

### Данные

```dart
class AppSettings {
  bool quietHoursEnabled;      // default true
  int quietStartMinutes;       // default 22*60
  int quietEndMinutes;         // default 8*60
}
```

Миграция: для существующих установок включаем `true` с 22:00–08:00. Это меняет
поведение уже созданных интервальных напоминаний, но в безопасную сторону: не
будит ночью. Если продукт хочет иначе — обсудить отдельно.

### Доступность и состояния

- Переключатель выключен: время и шкала приглушены, но видны; значения не
  редактируются.
- TalkBack: «Тихие часы, включены, с 22:00 до 08:00, 10 часов тишины».
- Часовые кнопки — 48 dp, открывают системный `showTimePicker` (24 ч).
- Шкала — декоративная; текстовая сводка обязательна.
- Тёмная тема: те же токены, заштрихованная тишина не становится невидимой.

### Что не входит

- Разные окна для разных привычек.
- «Не беспокоить» по календарю/геолокации.
- Перенос уведомлений на утро.
- Отключение только вечернего напоминания.

## 4. Первый запуск

### Проблема текущего онбординга

Три слайда обещают «Первую привычку добавим вместе», но после «Начать»
пользователь попадает в пустое «Сегодня». Обещание не выполняется, а первый
полезный шаг откладывается.

### Предложение: 2 шага

**Шаг 1 — ценность и приватность (без изменений по смыслу):**
«Маленькие шаги. Большие перемены.» + строка «Данные остаются на телефоне» +
«Продолжить» / «Пропустить». Никаких запросов уведомлений.

**Шаг 2 — «С чего начнём?»:**
- Три готовых варианта: «Пить воду», «Читать 20 минут», «Гулять 10 000 шагов»;
  у каждого — эмодзи, название, «Каждый день · напоминание в 08:00».
- «Своя привычка» — пустая форма.
- Выбранный вариант подсвечен `green50` + рамка `green600` + галочка.
- CTA меняет текст: «Добавить „Пить воду“». Открывает **предзаполненную форму**,
  а не создаёт сразу: пользователь видит, что можно изменить.
- «Позже» — закрывает онбординг и оставляет пустое «Сегодня» с тремя примерами.
- Внизу — строка приватности.

### Почему так

- Первая привычка создаётся в первом сеансе — главный успех онбординга.
- Нет обещания, которое не выполняется.
- Нет преждевременного запроса `POST_NOTIFICATIONS`: разрешение спрашиваем
  только при включении напоминания в форме, с объяснением.
- Приватность остаётся видимой, но не занимает отдельный слайд.

### Состояния и доступность

- `role=radiogroup`; выбранный вариант — `checked`; строки 58 dp, тап по всей.
- Фокус: заголовок → варианты → CTA → «Позже» → приватность.
- 320×640: контент скроллится, CTA закреплён внизу; при 360×800 всё влезает.
- «Пропустить» на шаге 1 и 2 завершает онбординг и ставит флаг.
- Флаг — существующий `onboardingCompleted`; миграция не меняется.
- Аналитики нет (офлайн); успех меряем по наличию первой привычки после
  онбординга, без отправки данных.

### Что не входит

- Выбор цели «3 раза в неделю» в онбординге — это второй экран формы, не первый запуск.
- Запрос уведомлений, аккаунт, подписка, выбор темы.
- Персонализация по полу/возрасту/целям.
